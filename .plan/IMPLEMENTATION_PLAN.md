## Blocking Swift 6.2 Build Problems (Must Fix First)

### 1) SwiftData `@Model` macro cannot expand on `let` property
- Symptom (compiler error):
  - `cannot expand accessor macro on variable declared with 'let'`
  - Origin: [TrackItem.swift](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/Model/TrackItem.swift#L12-L60) at `@Attribute(.unique) public let id: UUID` ([TrackItem.swift:L14](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/Model/TrackItem.swift#L14)).
- Root cause:
  - SwiftData `@Model`-persisted properties must be `var` so the macro can synthesize accessors/storage hooks.
- Fix:
  - Change `public let id: UUID` → `public var id: UUID` while retaining uniqueness attribute.
  - Re-run build; if migration is needed, add a migration step (see “SwiftData & Data Model Plan”).
- Acceptance criteria:
  - Debug build succeeds without the macro expansion error.
  - Existing SwiftData schema still enforces uniqueness of `id`.

### 2) EnvironmentKey defaultValue flagged as non-concurrency-safe global mutable state
- Symptom (compiler error):
  - `static property 'defaultValue' is not concurrency-safe because it is nonisolated global shared mutable state`
  - Origin: [CustomCover.swift](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/View/Utils/Modifiers/CustomCover.swift#L57-L60) at `static var defaultValue` ([CustomCover.swift:L58](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/View/Utils/Modifiers/CustomCover.swift#L58)).
- Root cause:
  - `static var` implies shared mutable global state under strict concurrency checks.
- Fix (preferred):
  - Implement `defaultValue` as an immutable constant:
    - `static let defaultValue = CustomDismiss()`
  - Alternative (only if justified): annotate as `@MainActor` if it must be actor-isolated.
- Acceptance criteria:
  - Debug build succeeds without the concurrency-safety error.
  - No additional global shared mutable state warnings appear for `EnvironmentKey` defaults.

### 3) DerivedData `lstat` errors are cascading (not root cause)
- Symptom (build system error):
  - `error: lstat(.../Objects-normal/.../Pasitea.swiftmodule): No such file or directory (2)` and similar for `.swiftdoc`, `.abi.json`, `.swiftsourceinfo`
- Root cause:
  - These appear after the compiler fails to emit the module due to earlier compile errors (like 1 and 2).
- Fix:
  - Treat these as a verification signal: once 1 and 2 are fixed, these should disappear.
  - If they remain, clean DerivedData and rebuild.

## Concurrency Problems (Strict Concurrency Findings)

### A) GCD background closures mutate main-actor-isolated SwiftUI state
- Where:
  - [CalmListenView.swift](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/View/Calm/Calm%20-%20Listen/CalmListenView.swift#L134-L150) (`DispatchQueue.global(...).async` inside `.onChange`)
  - [BreatheFlowerAnimation.swift](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/View/Calm/Calm%20-%20Breathe/BreatheFlowerAnimation.swift#L113-L138) (`DispatchQueue.global(...).async` inside button action)
- What the compiler is already warning about (will become errors under stricter settings):
  - `main actor-isolated property ... can not be referenced/mutated from a Sendable closure` (e.g. `@State` vars, `@Environment` modelContext, wrapper properties).
- Why it’s a problem:
  - SwiftUI view state (`@State`, `@Binding`, `@Environment`) is main-actor-bound by design.
  - GCD’s closure is treated as `@Sendable` for concurrency checking; touching main-actor state from it is a data race risk.
- Plan to fix (structured concurrency, no GCD):
  - Remove the `DispatchQueue.global` blocks entirely.
  - For any work that is actually expensive (e.g. audio file decoding), split into:
    - A detached task that produces a value (`AVAudioPlayer` or decoded data) without touching UI state.
    - A `MainActor` hop to assign to `@State` and interact with `ModelContext`.
  - Ensure all SwiftData `ModelContext` usage happens on the executor that owns it (in practice for SwiftUI’s environment context: main actor).
- Acceptance criteria:
  - No strict concurrency warnings remain in these views.
  - UI state changes only happen on main actor.
  - Audio switching remains responsive (no noticeable UI hitch when changing sounds).

### B) SwiftData `ModelContext` used from background thread
- Where:
  - [CalmListenView.swift](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/View/Calm/Calm%20-%20Listen/CalmListenView.swift#L134-L150) calls `item.saveInto(modelContext)` inside the background closure.
  - [BreatheFlowerAnimation.swift](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/View/Calm/Calm%20-%20Breathe/BreatheFlowerAnimation.swift#L113-L138) calls `trackItem.reset(modelContext, ...)` inside the background closure.
- Why it’s a problem:
  - SwiftData contexts are not generally thread-safe in an ad-hoc way; they are bound to specific executors/queues.
- Plan to fix:
  - Move all context interactions to main actor.
  - If background persistence is desired later, introduce a dedicated SwiftData “persistence actor” (see below) with its own context and strict API boundaries.

### C) Reference-type wrappers and stateful services are not Sendable
- Where:
  - [TrackItemWrapper.swift](file:///Users/gc/Developer/Aemi%20Studio.nosync/Pasitea/Pasitea/Model/TrackItemWrapper.swift#L11-L46) is a `class` holding a mutable `TrackItem`.
- Why it matters:
  - Under Swift 6 strict concurrency, passing reference types across tasks/actors is heavily scrutinized.
  - This wrapper is currently used from contexts that already violate actor rules (see A/B).
- Plan:
  - Short-term: ensure `TrackItemWrapper` is only ever used on main actor by removing background usage.
  - Medium-term: consider deleting the wrapper and replacing with:
    - Value-type “event” records (e.g. `TrackEvent`) that are `Sendable`.
    - A persistence layer that accepts those events and writes SwiftData models in one place.

## Proposed Concurrency Architecture (Target)

### UI layer
- Mark UI state owners as main-actor isolated:
  - SwiftUI Views remain implicitly main-actor-bound.
  - If introducing view models (`@Observable`), annotate them `@MainActor` and keep their dependencies `Sendable` where practical.

### Services layer
- Isolate mutable shared state behind actors:
  - `AudioPlaybackActor` (or similar) owns audio player lifecycle.
  - `TrackingService` / persistence facade owns the “start/end/reset” tracking semantics.

### Data flow
- Replace “mutate models directly from views” with “send events”:
  - Example events: `startedExercise(type, tags)`, `endedExercise(type, tags)`, `resetExercise(previousID, tags)`.
  - This reduces cross-layer coupling and prevents SwiftData objects from leaking into UI logic.
